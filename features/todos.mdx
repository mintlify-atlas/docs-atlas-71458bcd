Work Time Recorder includes a lightweight per-day todo list that lives in the right-side panel alongside the session history and statistics tabs. Each todo is scoped to a calendar date, so Monday's tasks never mix with Tuesday's. You can check items off as you complete them, edit titles inline, reorder them, and export or import the whole list as a CSV. When you are ready to start a work session, the "today's todos" dropdown lets you pick a task to pre-fill the work name — keeping your session names consistent without any extra typing.

## Accessing the Todos Tab

The right panel has three tabs: History, Todos, and Stats. Click the tab labelled **✅ 待办** (or select it with `data-view='todos'`) to switch to the todo view. The panel title updates to show either "今日待办" (today's todos) or the selected date string when you are browsing a past day.

The active view persists across page loads via `localStorage` (`rightPanelView` key), so if you had the Todos tab open when you closed the browser it will be the first thing you see when you return.

## Managing Todos

### Adding a todo

Type a task title into the input at the top of the panel and press **Enter** or click the **添加** button. The `addTodoFromInput()` function trims the input and calls `DataStore.saveTodo({ date, title })`. `DataStore.saveTodo()` normalises the record via `TodoModel.normalizeTodo()`, assigns a UUID, calculates the next `order` value for the date, then writes to localStorage and fires all `onDataChanged` listeners.

The `renderTodos()` function re-renders the list immediately after every mutation.

### Checking off a todo

Click the checkbox on any row. The `change` event calls `DataStore.updateTodo(id, { done: check.checked })`, which flips the `done` boolean and updates `updatedAt`. The row receives the `is-done` CSS class so completed items are visually distinguished.

### Editing a title inline

Click directly on the title text (the `<input type="text" class="todo-item-title">` element inside each row). Edit the text and then press **Enter** or click away. On `blur` or `change`, `commitTitle()` trims the new value and calls `DataStore.updateTodo(id, { title: next })` if the title actually changed. Empty titles are rejected — the field reverts to the stored value.

### Deleting a todo

Click the 🗑️ icon on any row. After a confirmation prompt, `DataStore.deleteTodo(id)` removes the record from localStorage and queues a sync operation if cloud sync is enabled.

## Date Filter

By default the panel shows today's todos. To browse another day:

1. Use the date picker (`todoFilterDate`) to select a date.
2. Click the **筛選** (filter) button — `todoDateValue` is updated and `renderTodos()` re-renders for the new date.
3. Click the **今天** (Today) button to reset `todoDateValue` to the current local date string and return to today's list.

The **清空** (Clear) button only removes todos for the currently-viewed date, not your entire history.

## Linking Todos to Work Sessions

Before starting a work session, a dropdown combobox next to the work name input lists today's incomplete todos. The options are generated by `TodoModel.workNameOptions(DataStore.getTodos(), today)`, which returns all non-deleted, non-done todos for today sorted by `order`.

Selecting an option copies its `title` into `workNameInput`. The link is title-only — no ID binding is created. If you later edit the todo's title, existing work session records are unaffected.

```js
// From refreshWorkNameCombobox() in script.js
const today = getLocalDateString(new Date());
const options = TodoModel.workNameOptions(DataStore.getTodos(), today);
```

## CSV Export and Import

### Export format

Click **📤 導出** to download all todos (across all dates) as a UTF-8 CSV with a BOM prefix. The file is named `待办_YYYY-MM-DD.csv`.

| Column | Type | Description |
|---|---|---|
| `date` | `YYYY-MM-DD` | The calendar date the todo belongs to |
| `title` | string | Task title (quoted if it contains commas or double-quotes) |
| `done` | `是` / `否` | Completion status |
| `order` | integer | Display order within the day (lower = higher in list) |

**Example:**

```csv
日期,标题,完成,排序
2024-06-10,Write release notes,否,0
2024-06-10,Update documentation,是,1
2024-06-11,Review pull requests,否,0
```

### Import

Click **📥 導入** and select a CSV file. Work Time Recorder calls `TodoModel.parseTodoCsv()` to parse each row. Valid rows are passed to `DataStore.importTodos()`, which generates **new UUIDs** for every imported row (so imports never overwrite existing todos) and merges them into the stored list. Up to **5 000** rows can be imported per file; files larger than **2 MB** are rejected before reading.

## DataStore API Reference

These are the public methods on `DataStore` that power the todos feature:

| Method | Description |
|---|---|
| `DataStore.saveTodo(todo)` | Normalise and persist a new todo; returns the normalised record |
| `DataStore.getTodos()` | Return all non-deleted todos across all dates |
| `DataStore.getTodosByDate(dateStr)` | Return todos for one date, sorted by `order` |
| `DataStore.updateTodo(id, patch)` | Merge `patch` into an existing todo and update `updatedAt` |
| `DataStore.findTodo(id)` | Return a single todo by UUID, or `null` |
| `DataStore.deleteTodo(id)` | Soft-delete a todo (removes from local storage, queues cloud delete) |
| `DataStore.importTodos(newTodos)` | Merge an array of todo objects, assigning fresh UUIDs; returns count |
| `DataStore.clearTodosByDate(dateStr)` | Remove all todos for the given date |

## TodoModel Schema

Every todo is normalised by `TodoModel.normalizeTodo()` before being written to localStorage. The resulting object always has the following fields:

| Field | Type | Description |
|---|---|---|
| `id` | UUID string | Unique identifier (generated via `crypto.randomUUID()`) |
| `date` | `YYYY-MM-DD` string | Calendar date the todo belongs to |
| `title` | string | Task title, max 80 characters |
| `done` | boolean | `true` when the task has been checked off |
| `order` | integer ≥ 0 | Sort position within the day |
| `updatedAt` | ISO 8601 string | Timestamp of the last modification |
| `deletedAt` | ISO 8601 string \| `null` | Set when the todo is deleted; `null` while active |

Todos with a non-null `deletedAt` are filtered out by all public read methods and never shown in the UI.
