Work Time Recorder stores all user data in four Tencent CloudBase document collections. Every document is automatically scoped to the authenticated user — the CloudBase SDK injects `_openid` on write, and the security rules enforce `doc._openid == auth.uid` on every read and write operation across all collections.

## Collections overview

| Collection | Document ID | Purpose |
|---|---|---|
| `work_records` | Record UUID | Completed work sessions |
| `todos` | Todo UUID | Daily task items |
| `user_settings` | User UID | Tags, alarm presets, theme |
| `active_sessions` | User UID | In-progress timer shared across devices |

## Security rules

All four collections share identical security rules. Apply the following in the CloudBase console under each collection's **Security Rules** tab:

```json
{
  "read": "doc._openid == auth.uid",
  "write": "doc._openid == auth.uid"
}
```

## Collection: `work_records`

Each completed work session is stored as one document. The document `_id` is set to the record's UUID, generated by `crypto.randomUUID()` or the UUID v4 polyfill in `DataStore.generateId()`.

```json
{
  "startTime": "2026-06-12T10:00:00.000Z",
  "endTime": "2026-06-12T12:00:00.000Z",
  "duration": 7200000,
  "workName": "Feature: login page",
  "updatedAt": "2026-06-12T12:00:00.000Z",
  "deletedAt": null
}
```

| Field | Type | Description |
|---|---|---|
| `startTime` | ISO 8601 string | Session start time (UTC) |
| `endTime` | ISO 8601 string | Session end time (UTC) |
| `duration` | number (ms) | `endTime − startTime` in milliseconds |
| `workName` | string | User-entered work description |
| `updatedAt` | ISO 8601 string | Last modification time — used for LWW merge |
| `deletedAt` | string or null | Set on soft-delete; `null` if active |

## Collection: `todos`

Each daily task item is stored as one document. The document `_id` is set to the todo's UUID.

```json
{
  "date": "2026-09-04",
  "title": "Write sync logic",
  "done": false,
  "order": 0,
  "updatedAt": "2026-09-04T09:00:00.000Z",
  "deletedAt": null
}
```

| Field | Type | Description |
|---|---|---|
| `date` | YYYY-MM-DD string | The day this todo belongs to |
| `title` | string | Task description |
| `done` | boolean | Completion state |
| `order` | number | Display order within the day |
| `updatedAt` | ISO 8601 string | Last modification time |
| `deletedAt` | string or null | Soft-delete marker |

## Collection: `user_settings`

One document per user, keyed by the user's UID. Stores app-wide preferences synced across devices.

```json
{
  "tags": ["Development", "Meeting", "Learning", "Debug", "Rest"],
  "alarmPresets": [5, 10, 15, 30, 45],
  "theme": "dark",
  "updatedAt": "2026-06-12T12:00:00.000Z"
}
```

| Field | Type | Description |
|---|---|---|
| `tags` | string[] | Custom work-category labels |
| `alarmPresets` | number[] | Timer alarm durations in minutes |
| `theme` | string | UI theme (`"dark"` or `"light"`) |
| `updatedAt` | ISO 8601 string | Last time any setting changed |

---

## Collection: `active_sessions`

One document per user, keyed by the user's UID. Holds the currently running timer so it can be displayed on other devices in real time via CloudBase's `watch()` API.

```json
{
  "startTime": "2026-06-12T10:00:00.000Z",
  "workName": "Feature: auth module",
  "isActive": true,
  "updatedAt": "2026-06-12T10:00:00.000Z"
}
```

| Field | Type | Description |
|---|---|---|
| `startTime` | ISO 8601 string or null | When the active session began; `null` when cleared |
| `workName` | string | Work description for the running session |
| `isActive` | boolean | `true` while the timer is running |
| `updatedAt` | ISO 8601 string | Timestamp of the last push from any device |

## Last-Write-Wins (LWW) merge

<Note>
  When the same record exists both locally and in the cloud, `SyncEngine.mergeRecords()` compares the `updatedAt` timestamps and keeps whichever version is newer. If the remote `updatedAt` is greater than or equal to the local value, the remote version wins and the local copy is overwritten. Records that are currently queued in the local pending-ops list are **never** overwritten by a remote pull — they retain their local version until they have been successfully uploaded.
</Note>

## Recommended indexes

Create the following **non-unique** composite indexes in the CloudBase console to support incremental pulls and sorted record listings:

```
work_records: (_openid ASC, updatedAt ASC)  — incremental pull queries
work_records: (_openid ASC, startTime DESC) — sorted record listing
todos:        (_openid ASC, updatedAt ASC)  — incremental todo pulls
```

<Warning>
  These indexes must be marked **non-unique**. Multiple records belonging to the same user can legitimately share an identical `updatedAt` or `startTime` value (for example, records imported in bulk). Creating a unique index will cause duplicate-timestamp writes to fail silently, causing the cloud record count to stall and backfill operations to loop indefinitely.
</Warning>
