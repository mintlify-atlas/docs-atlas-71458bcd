Work Time Recorder is a fully static web application — there is no build step and no server-side logic. Every file the browser needs lives at the repository root, which makes GitHub Pages an ideal zero-cost host. The repository ships with a GitHub Actions workflow at `.github/workflows/pages.yml` that detects every push to `main` and publishes the repo root automatically, so your instance stays current without any manual intervention.

## Automatic deployment

The fastest path to a live instance is to fork or clone the repository, push it to GitHub, and flip the Pages source to **GitHub Actions**. The workflow does the rest.

<Steps>
  <Step title="Fork or clone the repository">
    Fork the repository on GitHub, or clone it locally and prepare your own copy:

    ```bash
    git clone https://github.com/longlong007/work-time-recorder.git
    cd work-time-recorder
    ```
  </Step>

  <Step title="Push to GitHub">
    If you cloned instead of forking, create a new public repository on GitHub (no README), then push:

    ```bash
    git remote add origin https://github.com/YOUR_USERNAME/work-time-recorder.git
    git branch -M main
    git push -u origin main
    ```
  </Step>

  <Step title="Enable GitHub Actions as the Pages source">
    In your repository on GitHub, navigate to **Settings → Pages → Build and deployment → Source** and select **GitHub Actions**.
  </Step>

  <Step title="Save and watch the first deployment run">
    Click **Save**. GitHub immediately queues a deployment. Open the **Actions** tab to watch the workflow run. It typically completes in under a minute.
  </Step>

  <Step title="Open your site">
    Once the workflow shows a green checkmark, your instance is live at:

    ```text
    https://<YOUR_USERNAME>.github.io/work-time-recorder/
    ```

    Subsequent pushes to `main` redeploy automatically.
  </Step>
</Steps>

### Manual trigger

If you need to force a fresh deployment without changing any code, you can trigger the workflow manually:

1. Open the **Actions** tab in your repository.
2. Select **Deploy GitHub Pages** from the workflow list on the left.
3. Click **Run workflow → Run workflow**.

## Manual git deployment (alternative)

If you prefer the classic branch-based approach instead of the Actions workflow, follow these steps:

<Steps>
  <Step title="Initialise a local git repository">
    Inside the project directory, initialise git and make an initial commit:

    ```bash
    git init
    git add .
    git commit -m "Initial commit"
    ```
  </Step>

  <Step title="Create a public GitHub repository">
    Log in to GitHub, click **+ → New repository**, give it a name (for example `work-time-recorder`), set the visibility to **Public**, and — importantly — **do not** initialise it with a README or `.gitignore`.
  </Step>

  <Step title="Connect your local repository to GitHub">
    Add the remote and push. Replace `USERNAME` with your GitHub username:

    ```bash
    git remote add origin https://github.com/USERNAME/work-time-recorder.git
    ```
  </Step>

  <Step title="Push the main branch">
    ```bash
    git branch -M main
    git push -u origin main
    ```
  </Step>

  <Step title="Configure Pages to deploy from the branch">
    In your GitHub repository go to **Settings → Pages → Source**, choose **Deploy from a branch**, select **main** as the branch and **/ (root)** as the folder, then click **Save**. GitHub will build and publish the site within a few minutes.
  </Step>
</Steps>

## Updating your instance

After any change — whether you edited a file locally or merged a pull request — push to `main` and Pages rebuilds automatically:

```bash
git add .
git commit -m "update"
git push
```

Deployment typically completes within one to two minutes. Refresh the site and you will see your changes.

## Custom domain

If you own a domain and want to serve Work Time Recorder from it, go to **Settings → Pages → Custom domain**, enter your domain name, and click **Save**. GitHub will guide you through adding the required DNS records. HTTPS is provisioned automatically once the DNS record propagates.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Site shows 404 after deployment">
    Two things to verify:

    - The repository must be **public**. GitHub Pages is not available for private repositories on the free plan.
    - `index.html` must exist at the **repository root**. If it has been moved into a subdirectory, GitHub Pages will not find it.

    Check **Settings → Pages** to confirm the source is set correctly and that the most recent deployment succeeded (green checkmark).
  </Accordion>

  <Accordion title="Styles or scripts are not loading">
    The most common cause is that asset paths are absolute (`/style.css`) rather than relative (`./style.css`), which breaks when GitHub Pages serves the site under the `/work-time-recorder/` sub-path. Confirm that all HTML references use relative paths.

    Also verify that every required file has been committed — untracked or `.gitignore`-d files are invisible to GitHub Actions and will result in 404 responses for those assets.
  </Accordion>

  <Accordion title="Data appears missing or empty on first load">
    This is expected behaviour, not a bug. Work Time Recorder stores your records in the **browser's localStorage**. Each visitor — and each browser/device you use — has its own completely separate storage. Data you entered in one browser will never appear in another unless you export and import it manually.

    Clearing your browser's site data or cache will also erase all stored records, so use the application's built-in CSV export to keep backups.
  </Accordion>
</AccordionGroup>
